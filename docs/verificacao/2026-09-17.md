# Verificação do redesenho

Executada em 17/09/2026, na branch `codex/investigacao-de-gastos`.

## Testes automatizados

- Backend: **374 passaram**, em 115,15 s, com `python -m pytest -q`.
- Frontend: **22 passaram**, com `node --test frontend/tests/*.test.mjs`.
- Sintaxe dos cinco módulos JavaScript: validada com `node --check`.
- Revisão independente da base analítica, API/publicação e interface: realizada;
  os problemas encontrados foram corrigidos e reproduzidos novamente.

Os testes financeiros usam fixtures sintéticas. Cobrem moedas sem conversão,
exclusões de consumo, precedência de classificação, persistência e desfazer,
prévia de regras, compras parceladas, recorrências, cobertura e sincronização.
Os testes da API também cobrem origem/Host, token, revisões entre instâncias,
conflitos de escrita, caminhos estáticos e falha de publicação após salvar.

## Responsividade e acessibilidade

Inspeção visual em 1280 × 900 e 390 × 844, sem transbordamento horizontal da
página. Tabelas preservam rolagem dentro dos próprios painéis. No celular, os
filtros começam recolhidos; Enter os expande com `aria-expanded` atualizado.
Indicadores, barras e navegação são controles acionáveis por teclado; detalhes
usam diálogo nativo. A interface respeita redução de movimento.

Também foi inspecionado o layout a 640 px de largura, equivalente à largura
útil de uma janela de 1280 px com zoom de 200%. **O zoom nativo de 200% não foi
validado:** o navegador de teste não aplicou o atalho. A verificação de largura
não substitui todos os efeitos do zoom nativo.

## Decisões de integração

- Branch local no checkout existente para manter os dados e configurações no
  lugar. As alterações permanecem disponíveis para revisão; sem merge ou push.
- Ambiente virtual próprio usando as dependências já declaradas pelo projeto.
- Artefatos temporários de QA e revisão ficam ignorados pelo Git, separados
  dos dados pessoais; os percursos relevantes foram registrados aqui.
- Confirmações de recorrência abrangem estabelecimento e banco; médias são
  calculadas por conta, como informado na interface.

Dados incompletos continuam visíveis: o sistema não cria cotações, posições
históricas, associações de parcelas nem categorias aprovadas por suposição.
